# FitLog 4.0 — Body Studio

## Upgrade without losing data

1. In your existing FitLog 3.0 website, open Settings and export a complete backup **including photos** (encrypted if desired). Retain the passphrase separately.
2. Extract the release ZIP. Upload its **contents**, including `tests/`, `tools/`, `.github/` and `.nojekyll`, into the root of your existing GitHub repository, replacing same-name files. Do not create a new repository or change the website origin. Commit the update. The original static GitHub Pages deployment still works without build steps or API keys.
3. Wait for GitHub Pages to deploy. Reopen and refresh the existing site; a service worker update may require another reload or reopening the PWA. Do not clear browser storage. The header should say Body Studio · 4.0. Verify history, routines, measurements and photos before deleting your backup.
4. Open **Body → Open Body Studio**. All existing FitLog 3 features remain in their original screens. Data still uses the `fitlog-v1` storage key and `fitlog-pro-v2` IndexedDB database. The v3 payload schema is intentionally retained; the new optional `pro.v3.bodyStudio` extension is added lazily. Backups and encrypted backups include that extension; native photo storage is unchanged. Optional existing cloud sync merges the extension at the field level with conflict review; photos, generated mesh files and reports are not uploaded. A different origin or browser profile cannot access your old local storage; use backup restore instead.

## Using Body Studio

- Log measurements in Body, restore a FitLog backup, or download and fill the CSV template. The CSV header is `date,kind,value,unit`; dates use YYYY-MM-DD; supported units are `cm`, `in`, `kg`, `lb`, `%`, as appropriate. Blank template rows are ignored. Imports validate each nonblank row before saving, skip exact duplicates, and ask before importing same-day conflicts. The latest entry for a date wins for fitting; all recorded entries are retained.
- Height and body weight are helpful. Add neck, shoulders, chest, waist, abdomen, hips, upper arm, forearm, thigh, calf, wrist and ankle for better coverage. Separate left/right arm, forearm, thigh and calf entries supersede a shared measurement on each side. Shoulder width means outside-to-outside deltoid breadth; shoulder circumference means tape girth around shoulders and upper arms. Use consistent tape placement and relaxed posture. Values are converted to centimeters or kilograms internally.
- Select a date. Each snapshot uses the last entry for each kind at or before that date; invalid/out-of-range entries are flagged and omitted. Dates of carried-forward values are shown in the full fit table. No measurements means an explicitly labeled reference shape; missing height defaults to 175 cm. Missing circumferences are estimated, not fabricated records.
- Rotate the actual 3D mesh with drag, front/side/back buttons or keyboard arrows; pinch/scroll or use +/- to zoom. Muscle display colors estimated external regions, not anatomically isolated muscle volumes. Select a region by clicking it or using the dropdown. Suggestions use existing FitLog weekly muscle goals, recorded set counts and selected equipment. They do not infer muscle mass or recommend changing your body measurements.
- Compare with another date or a saved goal. Toggle transparent overlay, drag the blend slider or play the interpolation. The transition is a geometric morph, not a prediction of future results. Goal builder and simulator never edit the original measurement history; clear a simulated value to use an estimate. Save a goal separately; save manual shape corrections per recorded date. Manual adjustments are visual fullness and proportions, not measured regional fat percentages.
- Enable the optional photo panel to view the closest earlier Front/Side/Back photographs already in your local journal. They are not used in model fitting, analyzed, or sent externally. Photos are not included in reports. The base app's photos remain unencrypted at rest; encrypted backup is available.
- Export the displayed model as a Wavefront OBJ (cm, Y up, Z anterior; triangles and vertices). It contains an estimated body shape, not photos or identifiers. Import into Blender using appropriate scale; it is not a rigged or textured model. Export a self-contained HTML comparison report containing front, side and rear images and cross-section residuals. Open it to print/save as PDF using your browser. The Print / Save report as PDF button opens the same report; use the print button on that page. No direct binary PDF library is used.

## Geometry and accuracy limitations

The asset is a single connected, closed triangular surface with 21,756 vertices and 43,508 triangles, built from anatomical cross-section lofts with blended joints, face/neck, shoulder, torso, arm, pelvic, leg, foot and thumb contours. It is an original **stylized anatomical human mesh**, not a commercial photorealistic human scan. Hands, face, individual muscles, skin, posture and proportions are simplified; there is one reference body topology, with no sex-specific skeletal or tissue models. MakeHuman could not be retrieved during development and is not included. See `BODY_MESH_LICENSE.md` and `tools/build_mesh.py`.

The fitter scales height and iteratively adjusts transverse mesh slices. It computes segment lengths (shoulder and hip tape envelopes use convex perimeters) at fixed anatomical heights of the base pose. The shoulder width uses outside-to-outside geometry at the shoulder slice. Limb cross-sections are horizontal approximations, not perpendicular tape sections on angled limbs. Generic bilateral measurements are applied to both sides, but symmetry is reported only when explicit left/right values are available. Width and girth can conflict; extreme inputs may distort or overlap anatomy. The fitter bounds scaling, returns residuals and flags large errors; it does not certify no self-intersections for all deformations.

Weight/height ratio and body fat are modest shape priors for unspecified dimensions, not calibrated mass or regional adiposity estimates. The algorithm does not calculate medically meaningful body fat, match actual body volume to body weight, or infer tissue composition. Fitting RMSE is computed in cm over supplied geometric targets (including both sides if a generic measurement was supplied). Coverage counts supplied valid input fields out of 24 supported fields, not the percentage of body shape that is known. A small residual means that geometric slice matches its input; it is **not** a confidence score for real appearance. Manual shape corrections are applied after fitting and may increase residuals. No validated anthropometric error, clinical claim, or actual scan comparison is available.

The viewer uses local WebGL where supported; a genuine CPU-projected triangular 3D Canvas renderer is available if WebGL is unavailable. Both use the same mesh and geometry. The CPU renderer may be slower on mobile, and transparent overlay has approximate depth sorting. Body Studio requires JavaScript and Canvas; after the service worker caches the app, it needs no network. The existing YouTube and optional cloud features still need network. Report export depends on canvas image export support. All model processing is local. Optional cloud sync, if configured, may sync entered measurements, goals and corrections as part of the normal backup payload; avoid enabling sync if you want everything to stay on one device.

## Source structure

- `body-mesh.js`: vendored original mesh; no asset requests to third parties.
- `body-fit.js`: normalization, date snapshots, geometry fitting, residuals, symmetry and OBJ output.
- `body-view.js`: WebGL renderer, Canvas fallback, picking, rotation, zoom and overlay.
- `body-studio.js` and `.css`: app integration, controls, CSV import, reports and photo references.
- `tools/build_mesh.py`: reproducible asset generation; optional, no build required for deployment.
- `tests/body-fit.test.cjs`: geometry and fitting tests.
- `tests/body_browser_inline.py`: actual Chromium UI/Canvas tests with simulated origin storage.
- `tests/body_browser.py`: native IndexedDB, PWA caching and offline tests for GitHub Actions.

For the original training, nutrition, history, cloud setup and backup functionality, see the preserved FitLog 3.0 instructions below/in README. See `TESTING.md` for verified vs pending tests.
