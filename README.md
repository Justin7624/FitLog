# FitLog 3.0 — Training Studio

Private, local-first workout tracker for GitHub Pages. No framework, paid subscription, external build step, or account is required for local use.

## Upgrade an existing FitLog 1.0 or 2.0 installation

1. Open the **existing website on every device** with local records. Finish/discard any active workout. In Settings, export the JSON backup **with photos** (ordinary JSON is unencrypted, so keep it private). Store it outside your browser. If you already use cloud sync, reconcile devices first. Close older FitLog tabs to allow the IndexedDB schema upgrade.
2. Extract this release. Upload the files and folders to **the same GitHub repository and path** that you previously used. Replace the existing files. Include hidden `.nojekyll` and `.github/workflows/test.yml` (GitHub's file uploader may require creating `.github/workflows/test.yml` separately). Do not upload your personal backup or progress photos to the repository.
3. Commit, let Pages deploy, then reopen your original URL online. The original `fitlog-v1` localStorage key and the existing `fitlog-pro-v2` IndexedDB database name are retained. IndexedDB opens at version 2, adds the `snapshots` store without removing `photos` or `state`, and the v3 metadata migration preserves existing routines, exercises, IDs, logs, measurements and preferences. A previously valid older database snapshot is copied into the recovery store where available.
4. Verify the Arm Day log(s), routines, settings and gallery. If an old PWA is still showing, close it and reload the website after the service worker updates. **Do not clear site data.** If data appears missing, stop editing and check Settings → local DB recovery, or restore your backup. Migration is limited to the same browser origin/profile; changing device or site origin requires backup import or configured cloud sync. You cannot migrate data from a different browser remotely.
5. GitHub Actions runs the logic checks and browser acceptance tests on push. Check the **Actions** tab. The provided browser test suite has not passed in the author's environment (browser administrator policy prevented page navigation); see TESTING.md. Do not assume the workflow is green until you see the actual run.

For a fresh install, create a repository and use Settings → Pages → Deploy from a branch → main → / (root). The app seeds the original 18-exercise Arm Day (fitbymik, 45s work/15s rest, 10/12 lb editable defaults, linked video and timestamps) and November 23, 2026 historical record with unknown exact weights/reps. Ab Day and Leg Day are editable empty routines. Existing installations are not reseeded. Open the hosted HTTPS URL; on Android use Install app/Add to Home screen, on iOS Safari use Share → Add to Home Screen.

## Features and usage

- **Today**: next routine or scheduled rest/training day, recent work, weekly strip, quick actions, editable dashboard widgets (Settings).
- **History**: visible trash button, search, routine filters, duplicate same-routine/day warning at save, same-session ID upsert and double-save guard. Intentional same-day workouts can still be saved. Delete moves to Recently deleted for 30 days. Undo or Restore returns the same workout ID. Select two for comparison; merge reviews two matching date/routine sessions, appends distinct completed sets, keeps the first duration and saves both originals via revision/trash. Equal sets are treated as duplicates (they may have been intentional); review and edit after merge. Bulk delete supported. Routine and saved-workout edits have a limited revision log; restoring a revision overwrites that record, not the whole database.
- **Train**: edit routines and work sets, add/remove/reorder movements; browse/filter 160 distinct named exercise entries with original short form cues. Additional set types, RIR, RPE, side, tempo, explicit load convention, setup notes and progression mode. Circuit group labels cause guided sets to interleave by set number. The user chooses the same circuit group for exercises in a circuit. Manual rep sets need confirmation; timed sets auto-complete in guided mode. Planned weights are not verified actual loads; enter actual values before saving. Warm-up sets are excluded from enhanced working-set analytics. The old basic analytics still shows all completed sets and entered-load volume.
- **Guided video**: original YouTube links and chapter timestamps, embedded player on request, optional seek/play/pause commands from interval controls. The timer is the authoritative clock; YouTube may block embeds or autoplay. This is best-effort chapter command synchronization, not frame-accurate or bidirectional syncing. No arbitrary chapter extraction or automated rep counting. Enable sounds/speech/wake lock in Settings; availability depends on browser permissions, active screen and user gesture. A restored interrupted working timer pauses; review before resuming rather than crediting an unobserved completed interval. Background tabs may throttle timers; keep app visible during intervals.
- **Equipment**: Home/Gym profiles, equipment types and available dumbbells; named machine records with increments, maximum and seat/attachment notes. Match the exercise name exactly for adaptive machine increments.
- **Programs & schedule**: create a repeating multiweek sequence using the routine numbers or R (rest). Optional deload week labels; add/remove/move days. Plans do not modify the routine itself; exercise targets remain editable. Multiple planned entries on one date can be listed, but Today displays the first. No calendar integration or push reminders.
- **Adaptive training**: transparent two-session, effort-aware recommendations for double/linear progression; manual/timed modes; small available increments (maximum 15%) only. Timed sets use the previous duration/effort algorithm. RIR takes precedence over RPE when both are present. A repeated-high-effort heuristic can suggest a lighter week; no automatic prescriptions or medical clearance. Existing muscle map, substitutions, physique priorities and editable weekly goals remain available.
- **Progress**: existing exercise charts, muscle map, recovery-time estimates, estimated 1RM and basic records; enhanced direct/indirect coverage, recorded load convention, working sets, RIR, week-over-week counts, 28-day calendar heatmap and lifetime milestones. Per-dumbbell/two-side multiplier only when explicitly selected. Do not compare loads across different machines. Unknown loads/reps excluded from recorded volume. Muscle involvement labels and recovery estimates are approximations, not measurements of actual muscle recovery or hypertrophy. Outer quad development is represented as general quadriceps coverage.
- **Body**: existing measurements and ratios, added height and left/right measurements, 7/30-day recorded weight means, estimated fat/lean mass, waist/height ratio and measurement goals. Private progress photos stay in the existing IndexedDB store. Timeline, oldest/newest overlay slider and local timelapse slideshow. No exported video, photo alignment/cropping or encrypted photo storage at rest. You may include photos in an encrypted backup. Device/browser profile access can expose local data.
- **Wellness**: manual food, hydration and supplement journal, reusable templates, user-entered nutrient targets, 7-day calendar averages, dated check-ins with sleep/energy/soreness/stress and optional RHR/HRV. Not a food database, barcode scanner, supplement dosing advisor or clinical readiness score.
- **Reports**: Progress → PDF report. Select weekly, trailing 30-day, quarterly, trailing 365-day or all-time period; use Print / Save as PDF. Includes existing exercise/measurement tables, enhanced analytics, training chart, and achievements. Reports intentionally omit private photos. Some metrics (latest measurements, weekly goals, recent heatmap and all-time milestones) are labeled separately from the selected window.
- **Settings**: local backups, export CSV and JSON, optional photos, AES-256-GCM encrypted backup using PBKDF2-SHA-256 with 600,000 iterations and random salt/IV. Choose a strong passphrase; lost passphrases cannot be recovered. Encryption applies to the exported backup only, not ordinary data in localStorage, IndexedDB or Supabase. Keep unencrypted backups private. Hourly local rolling snapshots while the app is in use (up to 14, plus migration copy until retention prunes it). Restore is explicit and keeps local photos unless a photo backup is imported. Browser storage eviction or clearing can remove snapshots too; export off-device backups. The original localStorage-first design is retained for compatibility, backed by the IndexedDB mirror. Photos and the mirror use IDB transactions; this is not a complete transactional replacement of localStorage or a multi-tab collaborative database. Use one app tab per device.

## Optional cloud sync (Supabase)

Local operation is the default and does not send logs to a server. To configure private cloud sync:

1. Create a Supabase project you control, open SQL Editor, and run `supabase.sql`. The included SQL sets per-user row-level access on `fitlog_snapshots`. Review the security policies, project settings and your own backup procedures before use.
2. Create a confirmed email/password user under Authentication. In FitLog Settings, enter the HTTPS project URL, public publishable/anon key, email and password. Never enter a service-role or secret key. Sign in on each device. Tokens stay in memory and expire; sign in again after a reload or expiration.
3. Start with your primary device. Choose **Merge / sync now**. With a new account it creates the first snapshot. On a second device, import the primary backup before initial sync if possible, then sign in and choose Merge / sync now. Otherwise, review first-sync conflicts carefully: a fresh installation includes seed records with independently generated exercise/session IDs. Distinct records may be preserved as duplicate starter sessions. Review History and remove duplicates if needed.
4. After a common sync base exists, record-level three-way merge compares routine, session, measurement and other record IDs, handling nonconflicting additions/edits/deletions. Conflicting record paths are shown and you choose local or remote conflicting values; nonconflicting records remain merged. A server-side revision filter rejects stale writes. First sync/conflicts require manual confirmation. A legacy manual push/pull is still available in Settings but is whole-snapshot replacement; prefer merge. Export a backup before reconciliation. Automatic sync is opt-in, only while signed in, online, and no active workout, about once per minute; after reconnect it attempts another sync. Offline work stays local. No background account service, silent conflict resolution, persistent auth/refresh tokens, or sync of photos/active workouts. Live Supabase connectivity has not been tested against a real project; mock API tests are included.
5. Cloud data includes workout logs, routines, measurements, wellness journal, settings, recovery metadata, and history trash/revisions; photos and device timer preferences are excluded by the new merge sync. Cloud payloads are protected by your project's access controls and HTTPS, not end-to-end encrypted. If you prefer to keep all data local, leave cloud sync disabled.

## Architecture and development

- `app.js`, `library.js`, `pro.js`: original v1/v2 functionality and stable storage compatibility, with small migration/editor updates.
- `v3-core.js`: schema extensions, history management, revisions, encrypted backup and validation.
- `v3-training.js`: set metadata, circuits, progression, programs and video/wake features.
- `v3-ui.js` / `v3.css`: dashboard, screens, nutrition, photos, analytics and settings.
- `v3-sync.js`: optional record merge and automatic synchronization, local integration hooks.
- `sw.js`, `manifest.webmanifest`: cache only static app shell, installable PWA; videos and cloud require internet. Change cache version when releasing new builds.
- `window.FitLogIntegrations`: in-page read-only cloned workout/routine/measurement export hooks for future integrations, not a native health API or external service. Do not add untrusted scripts to this origin.
- `tests/`: synthetic v1 and v2 fixtures, logic tests and real browser acceptance tests. No private user data.

Run `node tests/core.test.cjs` with Node 22. For browser checks: `pip install playwright==1.52.0`, `python -m playwright install chromium`, `python tests/browser_test.py`. The script serves a temporary local HTTP site. See TESTING.md for verified and unverified functionality. Test workflow is included in `.github/workflows/test.yml`.
