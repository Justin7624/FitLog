# FitLog 2.0 · Training Studio

A mobile-first, local-first workout and body-composition tracker. Static HTML, CSS and JavaScript; no build step, paid API, dependencies or account required. Includes an installable web-app manifest and offline shell.

## Upgrade an existing FitLog 1.0 installation (recommended)

1. Open your **current** FitLog URL on your usual device/browser. In Settings, export the full JSON backup. Keep that file somewhere safe.
2. Extract the FitLog 2.0 ZIP. Upload/replace the files at the **same repository root and GitHub Pages URL**. Include the `.nojekyll` file and both PNG icons. Commit changes. Do not upload your personal JSON backup or photos to GitHub.
3. Open the same website in the same browser and refresh once Pages has deployed. If the old shell is shown, refresh again after the new service worker activates. Do not clear site data: that would remove your workout database.
4. Version 2 retains the existing `fitlog-v1` localStorage key and core schema version. It adds `pro.schema = 2`, stable exercise identities and an IndexedDB mirror. Existing routines, saved workout dates, set details, notes, measurements and history IDs are retained. Check History to verify your records. If moving to a different browser/origin or no history appears, import your exported v1 backup via Settings.
5. Export a new v2 backup after verifying your data. The database mirror is on this device, not a substitute for an external backup.

A fresh install includes Arm Day, Ab Day and Leg Day. The 18 Arm Day video chapters are preset to 45 seconds of work / 15 seconds rest with the original fitbymik video link. The November 23, 2026 Arm Day record is included; per-exercise actual weights/reps are intentionally blank. Planned 10/12 lb defaults are suggested and editable, not verified historic loads. Ab Day and Leg Day are empty for your own workouts. Migration never replaces existing v1 routines with these seeds.

## New installation on GitHub Pages

Create a GitHub repository, e.g. `fitlog`. Upload the extracted files **directly in the repository root**, not in an extra directory. Go to Settings → Pages → Deploy from a branch → `main` → `/ (root)`. After deployment visit `https://YOUR-USERNAME.github.io/fitlog/`. On iOS Safari use Share → Add to Home Screen; on Android Chrome use Install app/Add to Home screen. The first visit needs internet. Video playback and cloud sync also require internet. Browser storage is shared by origin; use the same browser profile and URL when upgrading. Different GitHub Pages repositories under the same username share the same origin, so avoid hosting multiple independent FitLog copies there with the same storage key.

## Daily use

- **Today:** next split routine, weekly goal, weekly activity, recent workouts, optional readiness check-in.
- **Train:** create/edit/duplicate routines; browse 76 exercises by name, muscle or equipment; add your own custom exercises; edit sets, seconds, reps, resistance, rest, notes, exercise order and timestamps. Training intelligence under each exercise provides compatible substitutions and conservative progression suggestions. Home and Gym profiles are editable; enter the equipment and actual dumbbell increments you own. Substituting creates a separate exercise identity and resets the planned sets; prior saved logs remain.
- **Live session:** enter actual weight, reps, seconds, RPE and set type; complete sets, add/reorder/duplicate exercises, edit date and notes, optionally update the template. Blank means unknown. The weight entry convention is per dumbbell for the Arm Day template; machine/other entries should follow a consistent convention. Do not interpret entered-load volume as summed two-dumbbell tonnage.
- **Guided session:** start from Train or the active workout. Load the optional privacy-enhanced YouTube embed or open video externally. The embed and interval timer are independent, not frame-synchronized. The chapter link loads a specific chapter. Press Start interval; timed work → rest → next timed set advances automatically; rep-based sets need manual completion. Edit weight, actual reps and RPE while training. Finish early, pause, skip or review; the guide does not auto-save a workout to History until you review and choose Finish. Leaving the guide or hiding the tab pauses it; reopening restores a paused interval. Timers are foreground tools, not guaranteed background alarms. Vibration depends on browser/device support. Actual YouTube embedding availability depends on YouTube and the video owner.
- **History:** calendar, edit/copy/delete logs, log a past workout, export CSV. Workout changes persist locally.
- **Progress:** 7/30/90/180/365-day and all-time filters, session/sets/volume/RPE statistics, weekly frequency, per-exercise records and trends, optional Epley e1RM (2–10 reps, non-time sets only), flat-load trend notice, front/rear interactive muscle schematic, primary and secondary set counts. Rename exercises without losing their identity-linked progress. Set personal weekly goals (defaults emphasize side delts, lats, quads and glutes). Recovery is a simple elapsed-time heuristic, not an actual measure of muscle recovery. Progress suggestions require recorded efforts/targets and repeated successful sessions; do not auto-increase weights. Training decisions should be based on comfort, technique and your own judgment.
- **Body:** log body weight, body fat and circumferences, chart trends, edit/delete records. Ratios use measurements on the same date and normalize units; lean mass is estimated from same-date weight and body fat. Add JPEG/PNG/WebP photos with date and front/side/back view; photos are compressed locally into JPEG and stored as blobs in IndexedDB. Select the same view to compare oldest vs newest. Photos are never sent by cloud sync. They are not encrypted at rest and are accessible to anyone who can access this browser profile. Backups including photos contain those images and should be stored securely.
- **Reports:** Progress → PDF report → Print / Save as PDF. Choose the range first. Uses the browser's native print dialog, with print-specific page formatting. No photos in reports. Select Save as PDF in the print dialog when available.
- **Settings:** theme, units, weekly workout goal, auto-rest, local database snapshot restoration, standard JSON backup, optional JSON backup with photos, CSV and cloud configuration. Backups replace workout data after confirmation; photo-inclusive backups also replace the local gallery. Standard v1/v2 backups leave existing photos untouched. Regularly keep an external backup.

## Optional Supabase cloud synchronization

The core app works without cloud configuration. The optional feature is **manual snapshot push/pull**, not automatic background merging. It syncs workouts, routine templates, measurement data, settings and goals. Progress photos stay local. Nothing is uploaded until you explicitly sign in and push. Data is protected by Supabase Auth and row-level security in your project; it is not end-to-end encrypted by FitLog. Account/project configuration and billing are your responsibility.

1. Create a Supabase project you control. In its SQL Editor, run `supabase.sql` included in the ZIP. This creates `public.fitlog_snapshots`, enables RLS, removes anonymous grants and grants authenticated users access only to their own row.
2. In Authentication → Users, create a confirmed email/password user. If only you will use the app, disable public signup in your project's Auth settings. Do not put the password in GitHub files.
3. In Project Settings / API Keys, locate the project URL (`https://<project>.supabase.co`) and **public publishable** (`sb_publishable_...`) or legacy `anon` key. Never use a service_role or secret key. FitLog rejects those types. Keep the SQL policies enabled; don't give anonymous access.
4. In FitLog Settings → Optional cloud sync, enter the URL, public key, email and password and sign in. The public URL/key and last acknowledged revision are saved in localStorage. Password and token are not saved; the token stays in memory. Sign in again after reopening/expiration.
5. On your first device, export a backup, then **Push local snapshot**. On another device, export its current data first, sign in, then **Pull cloud snapshot**. Pull replaces local workout data; it does not merge and it retains local photos. Thereafter push when done and pull before modifying on another device. Revision checks prevent silent overwrite of a changed cloud row. If a conflict occurs, back up both copies before reconciling. A new device must pull an existing cloud snapshot before pushing.
6. Sign out to clear the token. Forget cloud configuration removes saved URL/key and revision from this browser; it does not delete cloud data. To delete cloud data, use the Supabase console. Use the same account for your own devices only.

References: https://supabase.com/docs/guides/database/postgres/row-level-security and https://supabase.com/docs/guides/api and https://supabase.com/docs/guides/getting-started/api-keys.

## Testing

Run `node tests/core.test.cjs` from the repository root (Node 18+). No package installation required. The automated tests use a simulated DOM, controlled clock, in-memory browser storage and mock Supabase/IndexedDB interfaces. They cover the migration fixture, exact historical records, stable IDs, library filters, automatic work/rest transitions and save, muscle goals/coverage, measurement conversions, backups, recommended substitutions and progression, rendering of all main routes, report content, cloud API request shapes and revision conflicts. Actual live-browser navigation and print are blocked by the build environment's administrator policy, so native browser behavior, real YouTube playback, service-worker offline installation, image capture/compression and a live Supabase project are not end-to-end verified here. See TESTING.md for manual checks.
